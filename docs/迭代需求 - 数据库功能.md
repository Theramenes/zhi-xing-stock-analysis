## Roadmap

### Phase A: K线本地数据库 + 按需填充

**目标**: K 线存 SQLite，不预填全市场，用到哪只拉哪只

**核心原则**：
- 计算 B1 时总是先查 SQLite → 不够 114 天 → 自动补缺 → 再算
- 不主动批量拉全市场（收到股票列表时才拉）
- 每次补缺走四源降级，只拉实际缺失的交易日

| 步骤 | 内容 | 状态 |
|------|------|------|
| A1 | SQLite 建表 `stock_daily(code,date,OHLCV)` | ✅ 完成 |
| A2 | `ensure_candles(code, required_days=114)`: 查DB→算缺口→四源降级补→返回candles | 待实现 |
| A3 | `get_trading_days(start, end)`: date_sequence 拿交易日历 | 待实现 |
| A4 | B1 扫描器接入 `ensure_candles` 替代 `get_kline_range` | 待实现 |
| A5 | CLI `pull-kline --code 300083` 手动拉历史K线到DB | 待实现 |

**数据流**：
```
触发: 算B1 / 手动拉历史K线
  ↓
db.get_candles(code, 120)
  ├─ ≥114天 → 直接返回，算B1
  └─ <114天 → 算缺口
       ↓
     get_trading_days(last_date, today)          ← date_sequence
     missing = db.get_missing_dates(code, days)  ← SQLite 对比
       ↓
     for d in missing:
       get_kline_best(code, d, d)   ← 四源降级(history→snapshot→date_seq→free)
       db.upsert(code, candles)
       ↓
     db.get_candles(code, 120) → 算B1
```

### Phase B: 多数据源降级

**目标**: iFind → freeStockLine → akshare → 本地缓存，自动切换

| 步骤 | 内容 | 估时 |
|------|------|------|
| B1 | 抄 JusticePlutus 的 `DataFetcherManager` 优先级+指数退避模式 | 1h |
| B2 | 接入 akshare/efinance 做免费 K 线源（iFind 配额不够时兜底） | 1h |
| B3 | 安装验证：`pip install akshare efinance`，测试全市场批量拉取 | 30min |
| B4 | 熔断器：单源连续失败 N 次自动降级 | 30min |

**数据源优先级**：
```
① iFind date_sequence  (付费，优先，精确定制)
② iFind cmd_history    (付费，降级)
③ freeStockLine        (免费，不可靠但能用)
④ akshare/efinance     (免费，全市场批量，慢但全)
⑤ 本地缓存 SQLite      (离线，兜底)
```

## 实施顺序

```
Phase A (K线数据库)  ← 必须先做，后续所有依赖本地K线
  ↓
Phase B (多数据源)    ← A 把首次填充做好后，B 提供更多数据源选择
  ↓
Phase C (关注/持仓)   ← 有数据库后可以追踪变化
  ↓
Phase D (日快照)      ← 和 A3 互补（增量更新的一种方式）
  ↓
Phase E (飞书增强)    ← 最后的输出层优化
```
