# 知行股票分析系统 — 架构计划

## 背景

用户目前使用 OpenClaw 平台运行两个独立 skill（`tonghuashun-ifind-skill` 付费 + `freeStockLIneskill` 免费），存在数据源冲突问题：freeStockLine 无需鉴权检查，路由总是优先匹配到它，导致付费 iFind 数据源被绕过。用户已有完整的指标体系（知行超级B1、单针下20、B1B2B3、知行趋势线）、Python 计算器（知行B1.py）、扫描脚本（scanning.py、报告生成.py）、输出模板（板块扫描.md），现要在 Claude Code 中建设一个工程化的统一技能。

## 目标

1. **解决数据源冲突**：通过 SKILL.md 路由规则 + 鉴权门控，强制 iFind 优先、freeStockLine 为 fallback
2. **统一评估体系**：基于现有的 5 维持股评分 + agent-stock 的评估模型，构建综合评分引擎
3. **板块扫描工作流**：定义从板块发现→个股获取→指标计算→分类排序→报告生成的完整流程
4. **统一输出模板**：标准化 markdown 报告格式，覆盖全市场扫描、板块深度、持仓评估、早盘前瞻

## 二、SKILL.md 核心设计（解决冲突的关键）

### 数据源优先级表（硬编码，不可违反）

| 优先级 | 数据类型 | 主数据源 | 降级数据源 |
|--------|---------|---------|-----------|
| 1 | K线历史/实时行情/财务/板块/资金流/龙虎榜 | iFind | freeStockLine |
| 2 | 新闻/公告/舆情 | freeStockLine | N/A |
| 3 | 指标计算/评分 | LOCAL（知行B1.py） | N/A |

### 鉴权门控规则（核心修复）

- 任何 iFind 查询前：检查 access_token 有效性
- 若 token 无效：**禁止静默降级**，必须提示用户选择：(a) 输入 refresh_token (b) 使用免费源
- 只有用户明确使用关键词（"免费"、"free"、"不用ifind"）时，才跳过 iFind
- 降级时必须警告用户："iFind查询失败，已切换至免费数据源，数据精度可能下降"

### 用户覆盖关键词

- `优先免费源` / `用免费数据` → 跳过 iFind，直接免费
- `只用ifind` / `付费数据` → 跳过免费，仅 iFind
- `双源对比` → 双源查询并显示差异

### 能力边界

- 支持：全市场B1扫描、板块深度扫描、持仓评估、个股分析、早盘前瞻、缩爆B1扫描
- 不支持：Level-2数据、期货/期权、自动交易执行、投资建议

## 四、评估/评分引擎

### 5维度 + 权重

| 维度 | 权重 | 关键指标 |
|------|------|---------|
| B1信号质量 | 30% | 基础B1/B2/B3 + 超级B1(7种) + 共振加分 |
| 趋势质量 | 20% | 白线vs黄线方向、BBI持续向上、超牛股/强趋势股判定 |
| 量能状态 | 15% | 超缩量>适当缩量>缩量>放量阳>大绿棒 |
| 异动活跃度 | 20% | 洗盘异动/聚宝盆/双叉戟/近期振幅/远期振幅 |
| 风险评分 | 15% | 持股评分(0-5) + 单针下20 + 死叉/破线/转势 |

### 一票否决（评分前执行）

1. 涨停封死（涨幅≥9.5%）→ 否决
2. ST/*ST → 否决
3. 日成交额 < 1000万 → 否决
4. 重大利空公告/巨量解禁(5日内) → 否决

### 综合分 = clamp(Σ(维度分×权重) + 共振加分 - 风险罚分, 0, 100)

等级：S级(90-100) / A级(75-89) / B级(60-74) / C级(40-59) / D级(0-39)

## 五、板块扫描工作流（5阶段）

```
阶段1: 板块发现
  → iFind smart-query "行业板块涨跌幅排行"
  → 过滤（成分股<5剔除）+ 排序（涨跌幅+资金流）
  → 交叉用户关注列表

阶段2: 个股获取
  → 对每个板块取成分股 code+name
  → 20线程并行取K线（iFind主 / free降级）
  → 缓存到 scan_cache.json

阶段3: 指标计算
  → 每只股票跑 b1_calculator.py（120日K线 → 完整指标JSON）
  → 再跑 scoring.py（指标JSON → 综合评分+等级+维度明细）

阶段4: 分类排序
  → Tier1: B1信号 / Tier2: 近B1(J<20) / Tier3: 趋势持有 / Tier4: 其他
  → 按综合评分 + 信号数量 + 共振加分排序
  → 行业聚合：B1密度、近B1密度、综合强度排行

阶段5: 报告生成
  → 按统一模板输出 markdown
  → 可选：发布到飞书文档
```

## 六、输出模板规范

统一模板包含8个板块（与现有 `模板/板块扫描.md` + `报告生成.py` 合并）：

1. 大盘状态（指数/涨跌比/成交额/情绪）
2. 行业板块B1强度排行
3. B1信号标的（A级及以上）
4. 近B1观察区（J<20）
5. 持仓个股详细分析（含操作预案）
6. 关注板块个股深度
7. 缩爆B1候选
8. 风险提示

#### 3a. 板块概览（scan-sector-overview）

**数据流**：
```
用户: "扫电池行业"
  ↓ SKILL.md 路由: 不含"B1"关键词 → 板块概览模式
  ↓
① 板块定位（sector_routing.md 规则）:
   - 含"行业"→ searchstring="电池行业" → endpoint-call a_share_common_query
   - 含"概念"→ searchstring="锂电池概念" → endpoint-call
   - 两者都提 → 只走行业，提示用户概念不作分析
   - 模糊 → 从同花顺拿细分行业列表，让用户确认
  ↓
② iFind 查成分股 + 资金流 + 龙头 + 异动标签:
   searchstring="{名称}行业 资金流向 概念龙头 股票市场类型"
   → 返回每只股票的 所属同花顺行业 / 资金流向 / 概念龙头 / 市场类型
  ↓
③ 本地聚合（按 细分行业 = 三级行业 分组）:
   - 如果查的是一级行业 → 按二级/三级拆表
   - 计算每组: 近3/5日涨跌均幅、资金净流入合计、涨跌停家数
   - 识别每组的核心龙头（概念龙头字段 + 市值加权）
   - 标记异动标的（涨跌幅>5% / 量比>3 / 资金异常）
  ↓
④ 行业内部逻辑分析:
   - 提取该一级行业下所有二级/三级子行业
   - 分析上下游关系（如: 锂矿→电池化学品→锂电池→新能源车）
   - 输出行业结构图（ASCII art 或 mermaid）
  ↓
⑤ 报告输出（对齐 templates/板块扫描.md）:
   > 1. 行业板块逻辑梳理（行业关联图+内部逻辑说明）

   > 3. 核心与异动标的（龙头+异常波动）
   > 4. 涨跌停统计
   ↓
⑥ 飞书知识库发布
```
